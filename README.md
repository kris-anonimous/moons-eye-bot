# Moons Eye Bot

Telegram-бот на aiogram 3.x + Motor (MongoDB) + FastAPI/uvicorn, с Google
Gemini API для подбора ролей и части модерации. Рассчитан на запуск как
Hugging Face Space (веб-сервер на порту 7860, вебхук).

## Переменные окружения

| Переменная              | Назначение                                                        |
|--------------------------|--------------------------------------------------------------------|
| `BOT_TOKEN`              | токен бота от @BotFather                                           |
| `GEMINI_API_KEY`         | ключ Google Gemini API (бесплатный тариф)                          |
| `MONGO_URI`              | строка подключения к MongoDB (например, MongoDB Atlas)             |
| `OWNER_ID`               | Telegram ID владельца                                               |
| `MAIN_CHAT_ID`           | ID основного чата                                                   |
| `LOGS_CHAT_ID`           | ID чата для логов                                                   |
| `REQUIRED_CHANNEL_IDS`   | ID обязательных каналов через запятую, напр. `-100123,-100456`     |
| `BASE_WEBHOOK_URL`       | внешний URL пространства, напр. `https://user-space.hf.space`      |
| `AGREEMENT_URL`          | ссылка на пользовательское соглашение (необязательно)               |
| `GEMINI_MODEL`           | модель Gemini (по умолчанию `gemini-2.5-flash`)                    |
| `GEMINI_FALLBACK_MODELS` | запасные модели через запятую (по умолчанию `gemini-flash-latest`) |
| `PORT`                   | порт веб-сервера (Hugging Face сам подставляет 7860)                |

Модели Gemini Google периодически отключает без предупреждения (в мае 2026
так отключили 1.5 и 2.0). Если в логах появляется `404` по модели — впишите
актуальное имя в `GEMINI_MODEL` без переразвёртывания кода.

## Права бота

- В основном чате: администратор с правами банить, ограничивать, удалять
  сообщения, приглашать по ссылке, управлять тегами участников
  (`can_manage_tags` — доступно с Bot API 9.5).
- В обязательных каналах: администратор с правом банить.
- **Group Privacy = Off** у @BotFather (`/setprivacy` → Disable) — иначе бот
  не увидит обычные сообщения в группе.
- **Join Requests** обязательно включены в настройках чата — вся логика
  приёма построена на `chat_join_request`.

## Архитектура

- `config.py`, `roles.py`, `roles_data.py` — настройки и список ролей
  (`roles_data.py` — список ролей, дословно скопированный из ТЗ; `roles.py`
  его разбирает на имена/фамилии/пол без побочных зависимостей).
- `services/pure.py` — чистые функции без сети и БД (разбор ролей, дат,
  форм, тегов) — при желании их можно тестировать напрямую.
- `services/utils.py` — отправка с копией в лог, права чата, `/everyone`.
- `services/texts.py` — реестр редактируемых текстов (раздел «Редактирование»
  в /admin), поддерживает HTML-разметку и до 2 фото на текст.
- `services/gemini_service.py` — подбор роли и контекстная модерация.
- `services/recruitment.py` — фазы/волны/режим ожидания/брони.
- `services/punishments.py` — единая лестница наказаний.
- `services/scheduler.py` — все фоновые задачи (APScheduler).
- `database/methods.py` — весь доступ к MongoDB.
- `database/storage.py` — хранилище состояний анкет (FSM) в MongoDB, чтобы
  перезапуск Space не обнулял заполняемые анкеты.
- `handlers/*.py` — обработчики.

## Как разрешены неоднозначности ТЗ

Прежде чем писать код, было зафиксировано 30 неоднозначностей ТЗ (владелец
ответил на каждую). Основные решения:

- Волна 1 — максимум 10 мест, Волна 2 — максимум 20 (шаблон по умолчанию,
  если владелец не ответил вовремя: 10 и 15 соответственно).
- Вход засчитывается в фазу сразу при входе в чат; непройденная капча
  откатывает счётчик и, если именно этот вход закрыл фазу, возвращает её.
- Проверка «места в фазе» и «свободна ли роль» — раздельные, роль проверяется
  всегда, независимо от статуса фазы.
- Уже одобренная заявка действует даже при начале режима ожидания.
- Бронь: нельзя сменить роль и передумать самому (аннулировать может только
  событие, из-за которого роль стала недоступна); срока действия нет; при
  бане или занятии роли иным путём бронь аннулируется автоматически.
- Всего 3 попытки анкеты (1 + ещё 2), после чего — принудительное ожидание
  следующей волны.
- 5 часов на переход по ссылке считаются от её создания.
- 5 минут на капчу считаются от входа в чат.
- Юзернейм: 30 минут считаются с момента, когда бот обнаружил его
  отсутствие; после разблокировки/`/start` цикл начинается заново.
- 29 февраля принимается, только если текущий год — високосный.
- Обычный админ видит те же разделы, что участник, но без кнопок
  взаимодействия («Поддержка», «Жалобная», «Взять рест»).
- Третьего администратора назначить нельзя — кнопка недоступна, если два
  админа уже назначены.
- Ночной режим — по МСК, отключаются все виды вложений.
- Оба ID в `REQUIRED_CHANNEL_IDS` — обязательные каналы, доступные боту.
- Повторная жалоба того же человека на одну и ту же цель не увеличивает
  счётчик (считаются уникальные жалобщики): 11-й уникальный — мут, 21-й —
  бан.
- Gemini только классифицирует нарушение по номеру правила; конкретное
  наказание бот берёт из таблицы правил сам.
- Предупреждение о превышении лимита `/everyone` официально засчитывается
  как устный варн — реализовано буквально (устные варны растут при каждом
  предупреждении, накопление до варна работает как обычно).
- Месячная норма сообщений = 4 недельных нормы (по умолчанию 560 = 4×140).
- Активностью для чисток/неактива считаются только сообщения в общем чате.
- Если у третьего места в топ-3 недостаточно сообщений — топ не выводится
  вообще (ни одно место).
- Владелец не исключается из статистики/списков, но модерация к нему
  слепа.
- При выходе/исключении участник полностью стирается из базы, **кроме**
  поданных на него жалоб (они остаются в отдельной коллекции).
- Роль освобождается автоматически, как только запись участника стёрта.
- Раздел «Редактирование» — текст можно менять для любого экрана, кроме
  самих inline-кнопок; фото — до 2 на текст.
- Согласием с пользовательским соглашением считается нажатие кнопки
  «Принять».
- Список ролей — источник истины; Gemini используется только для гибкого
  сопоставления введённого текста с этим списком.

## Что стоит знать перед боевым запуском

Проект такого объёма нельзя протестировать без реального чата, каналов и
MongoDB — синтаксис всех файлов проверен (`py_compile`), но полноценного
прогона с реальными Telegram/MongoDB/Gemini не было. Отдельно стоит знать:

1. **Теги участников** (`setChatMemberTag`) — совсем новая возможность Bot
   API (добавлена в районе версии 9.5). Если в вашей версии aiogram или у
   Telegram на момент запуска её ещё нет/она недоступна для вашего бота,
   вызовы тихо логируются как предупреждение и не ломают остальную логику
   — просто тег не проставится.
2. **Оценка «твинк ли аккаунт»** по id — Telegram не отдаёт дату регистрации
   напрямую; в `config.USER_ID_DATE_ANCHORS` заданы примерные опорные точки
   «id → дата» по наблюдениям сообщества, которые устаревают со временем и
   стоит периодически обновлять.
3. **Анализ медиа** (правила 3.0/3.5) через Gemini для видео и GIF (`animation`)
   проверяет только превью-кадр, который присылает сам Telegram, а не всё видео
   целиком — если недопустимое появляется глубже в ролике, а не на стоп-кадре,
   бот это не поймает. Для фото и статичных стикеров проверяется полное
   изображение. Правило 3.4 (скримеры/неприятные звуки в видео) вообще не
   проверяется автоматически — это требует анализа движения/звука во времени,
   а не статичного кадра, и не покрывается текущим подходом; применяется
   только вручную, реплаем в формате «Нарушение по 3.4 / Наказание: ...»
   (эта ручная система работает для любого правила, не только автоматических).
4. **Изменение времени чисток** через админ-панель применяется сразу же —
   перезапуск бота для этого не нужен (используется `scheduler.reschedule_job`
   через `dp["scheduler"]`, доступный хендлерам).
5. Бесплатный тариф Gemini ограничен по частоте запросов — в
   `config.GEMINI_MAX_CALLS_PER_MINUTE` задан свой лимитер; при превышении
   анализ конкретного сообщения просто пропускается, а не встаёт в очередь.
6. **Редактирование текстов** (`services/texts.py`) покрывает весь текст,
   который реально нужно было вынести под редактирование по смыслу ТЗ, но не
   абсолютно каждую короткую служебную строку в коде (например, отдельные
   сообщения об ошибках формата вроде «Введите число.» остаются в коде) —
   это сознательная граница, не недочёт: такие строки не несут
   пользовательской нагрузки и их тексту пользователи, по сути, не видят
   смысла менять.
7. Счётчик «рейд/спам прямо сейчас» (всплеск сообщений за 10 секунд) живёт
   только в памяти процесса и сознательно не хранится в MongoDB — это
   счётчик текущего момента, а не часть истории нарушений (сама история —
   варны, баны, причины — вся в базе). Если бот перезапустится ровно в
   середине атаки, счётчик обнулится; это крайний и очень редкий случай.
8. Ночной режим управляется через `setChatPermissions` на уровне всего
   чата — это намеренное решение, а не недочёт: Telegram сам по себе не
   применяет такие ограничения к администраторам и владельцу чата, поэтому
   отдельно прописывать исключение для них не требуется.
